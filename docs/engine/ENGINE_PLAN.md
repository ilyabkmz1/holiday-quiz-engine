# Конструктор новогодних квизов под ключ: движок + агент-сборщик

## Контекст

Исходный квиз, из которого вырос движок, был сделан под одного заказчика и уже был наполовину конфигурируемым. Тексты заданий, героев, комнат, финального рывка, призов и юр.тексты лежали в `src/config/campaign.ts` и проверялись zod-схемой (`src/config/schema.ts`). Но:
- **Бренд захардкожен.** Лого заказчика, metadata, OG-картинка, письма, share-текст, CSS-палитра (`theme.ts` нигде не используется), метафора «офис в снежном шаре / ёлка / игрушки».
- **Мир квеста захардкожен.** `quest/world-data.ts` содержит узлы, рёбра, `ROOM_SPOTS` по id комнат первой кампании и `HAIR` по id героев. Арт привязан к id в `room-ui.tsx` и `ambient.tsx`.
- **Количества жёсткие.** 5 комнат × 3 задания, 6 героев, 4 уровня призов. Пороги призов заданы в абсолютных очках.
- **Одна кампания на сборку и одну ВМ.** Конфиг импортируется статически в `server/container.ts`. При этом БД уже готова к нескольким кампаниям: есть `campaignSlug`.

Цель: продавать квизы СМБ под ключ. Заказчик заполняет ТЗ и даёт сайт, лого или хотелки. Агент (Claude Code или Codex) собирает квиз **из кубиков** и не пишет код. Агент заполняет пакет арендатора, прогоняет автоматические проверки и выкатывает превью.

Решения пользователя:
- Хостинг: общий сервер для всех, а по желанию клиента — на его сервере.
- Миры: базово библиотека шаблонов, а для нестандартных бизнесов (тайский спа, детский сад) нужен путь «свой мир».
- Агент: Claude Code или Codex со скиллом.
- Аудитория: и клиенты бизнеса, и сотрудники.

## Главный принцип: агент собирает данные, а не код

```
Бриф клиента ─┐
Сайт / лого ──┼─► агент ─► tenants/<slug>/ ─► quiz:check ─► превью ─► правки ─► запуск
Хотелки ──────┘            (pack.json + assets)  (схема, симуляция,
                                                   скриншоты)
```

Каждый клиент — это папка-пакет. Движок общий. Агент работает только через схему и CLI-скрипты. Поэтому ошибки ловит валидатор, а не ревью кода, и сборка одинаково работает в Claude Code и Codex.

## Кубики (что агент комбинирует)

| Кубик | Что это | Откуда берётся |
|---|---|---|
| **Brand kit** | цвета (8 токенов), шрифт из allowlist, лого, имя бренда, тон | агент извлекает с сайта (`quiz:brand <url>`) |
| **World** | иллюстрация + `world.json` (узлы, дорожки, спот-точки зон, слоты коллекции, огни, зона финала) | библиотека `worlds/<id>/` или «свой мир» |
| **Story** | метафора: что собираем («игрушки на ёлку», «подарки в мешок», «огоньки гирлянды»), имя гида, пролог | словарь пресетов + правка агентом |
| **Zone** | комната/зона = тема бизнеса (услуга, продукт, ценность) | бриф → маппинг на спот-точки мира |
| **Hero** | NPC с параметрическим спрайтом (цвет, причёска, аксессуар) | конфиг (вместо `HAIR[hero.id]`) |
| **Task block** | `pick`, `build`, `order`, `access`, `odd-one-out` (обобщённый `phish`), позже `true-false`, `match` | таблица «какой контент → какой блок» в скилле |
| **Finale** | финальный рывок (30-секундная сортировка) on/off | конфиг |
| **Reward module** | `claim` (приз по email), `promo` (промокод по уровню), `lead` (форма заявки), `leaderboard` (сотрудники/команды), `none` | флаг + параметры |
| **Copy pack** | все UI-строки с дефолтами, которые можно переопределить | `copy` в пакете |
| **Legal** | оператор ПДн, политика, согласие | бриф (юрлицо клиента) |

## Этапы работ

### Этап 0. Первая кампания становится эталонным арендатором (страховочная сетка)
- Перенести `campaign.ts`, `legal.ts` и арт в пакет арендатора (сейчас эталон — `tenants/demo-office/`), мир шара — в `worlds/snow-globe/`.
- Критерий: все существующие unit-, integration- и e2e-тесты проходят без изменения поведения. Это эталон регрессии.

### Этап 1. Формат пакета и загрузчик
- **Схема.** `src/config/schema.ts` разбить на `packSchema = { brand, story, copy, legal, campaign, worldId, reward }`.
- **Количества → диапазоны.** Зоны 3–6, задания 2–4 на зону, уровни 2–5, герои 1–8.
- **Пороги уровней в % от максимума.** Максимум считается из `domain/scoring.ts`, а `resolveReward` уже работает с любым числом уровней.
- **Новые проверки схемы.** Сервис рывка ↔ id зоны (сейчас скрытая связь в `QuizGame.tsx:264`), имена иконок ∈ ключи `icons.tsx` (сейчас тихий фолбэк), каждая зона привязана к спот-точке мира.
- **Реестр.** `src/server/tenants.ts` загружает все пакеты, валидирует их на старте и выбирает арендатора по `Host` (поддомен или кастомный домен) либо по env `TENANT=<slug>` для однопользовательского режима.
- **Container.** `server/container.ts` строит сервисы на каждого арендатора: в Map по slug вместо статического импорта. `presentation.ts` уже принимает campaign аргументом.
- **Seed.** `prisma/seed.ts` сидит все пакеты. Модель БД почти не меняется: `campaignSlug` уже есть, уникальность `[campaignSlug, normalizedEmail]` сохраняется.
- **Инварианты из CLAUDE.md сохраняются.** Очки считает только сервер. Правильные ответы не уходят до фиксации ответа: `publicCampaign` должен вырезать их из каждого блока.

### Этап 2. Бренд и тексты из пакета
- **Палитра.** Токены `brand.colors` инжектятся в `:root` через `<style>` в `layout.tsx`. В `globals.css`, `quest.css`, `share.css` и `admin.css` захардкожено ~90 hex — заменить их на `var(--…)`. Шрифт выбирается из allowlist `next/font`: 5–6 кириллических.
- **Брендированные места.** Лого, metadata, `siteName`, OG-картинка (`server/share-image.tsx`), письма (`mailer.ts`), share-текст и basic-auth realm — всё берётся из пакета.
- **Тексты.** UI-строки выносятся в `copy` с дефолтами. Метафору «ёлка / игрушки / снежный шар» и реплики робота-помощника дают `story`-поля.
- **Контраст.** Автопроверка WCAG для пар текст/фон: агент часто берёт неудачные цвета с сайта.

### Этап 3. Миры: библиотека и «свой мир»
- **`world.json`.** `quest/world-data.ts` превращается в загрузчик `worlds/<id>/world.json` (nodes, edges, spots[], collectSlots[], rushRect, lights[], robotHome). Зона пакета ссылается на `spotId`, а не на захардкоженный room id. Огни из `ambient.tsx` и арт из `room-ui.tsx` тоже переезжают в `world.json`.
- **Перекраска под бренд.** Арт мира — нейтральная иллюстрация плюс тонируемые слои (CSS `mix-blend` / SVG-маска акцентов) и слот под лого (вывеска, флаг, коробка).
- **Стартовая библиотека** из 4 миров на разные сегменты СМБ:
  - `snow-globe-office` — уже есть;
  - `winter-street` — магазин, кафе, салон;
  - `cozy-house` — спа, детский сад, клиника;
  - `workshop` — склад, производство, доставка.
- **Свой мир.** Генерация иллюстрации по промпту бренда (стиль задаётся референсами из библиотеки), затем разметка в редакторе `/dev/world-editor`: клик по картинке ставит узлы, рёбра и споты, экспорт даёт `world.json`. Агент может предложить разметку сам, а потом проверить проходимость скриптом (граф связный, каждый спот достижим из старта) и посмотреть скриншот. Человек правит в редакторе. Это платная опция, потому что требует ручного контроля.
- **Режим карточек** (`mode: "cards"`) остаётся дешёвым тарифом: ему нужны только фон и точки зон.

### Этап 4. Инструменты агента (CLI, одинаковые для Claude Code и Codex)

| Команда | Что делает |
|---|---|
| `npm run quiz:new <slug> --brief brief.md` | Создаёт `tenants/<slug>/` из шаблона, переносит поля брифа |
| `npm run quiz:brand <slug> <url>` | Через Playwright снимает сайт: computed-цвета, шрифты, favicon, og:image, лого → `brand` + `assets/` |
| `npm run quiz:check <slug>` | zod-схема, семантический линт (утечки в id через `REVEALING_ID_PATTERN`, длины строк под UI, контраст, иконки, связность мира), симуляция (идеальный и нулевой проход, достижимость каждого уровня приза) |
| `npm run quiz:shots <slug>` | Скриншоты всех экранов (mobile + desktop) в папку, чтобы агент сам проверил вёрстку |
| `npm run quiz:preview <slug>` | Выкатывает на staging-поддомен с паролем и возвращает ссылку для клиента |
| `npm run quiz:export <slug>` | Образ + `.env` в однопользовательском режиме для сервера клиента |

Переиспользуется:
- `tests/support/solve.ts` — для симуляции;
- e2e-сценарии — их параметризовать по арендатору, селекторы брать из `copy`, а не из строк конкретного пакета;
- `deploy/` скрипты.

### Этап 5. Скилл агента
- **Скилл** `.claude/skills/build-quiz/SKILL.md`. Для Codex то же самое — ссылкой из `AGENTS.md`.
- **Шаблон ТЗ** `docs/brief-template.md`:
  - бизнес и сегмент;
  - кто игроки (клиенты или сотрудники);
  - цель (лиды, промокоды, вовлечение, обучение);
  - 3–6 тем, продуктов или ценностей;
  - факты для вопросов;
  - тон;
  - призы и уровни;
  - даты;
  - сайт, лого, хотелки по дизайну;
  - юрлицо;
  - домен или хостинг.
- **Шаги скилла:**
  1. Разобрать бриф и задать клиенту вопросы только по пробелам.
  2. Собрать brand kit.
  3. Выбрать мир по таблице «сегмент → мир» или пометить, что нужен свой.
  4. Выбрать метафору и маппинг «тема → зона → спот».
  5. Сгенерировать задания по таблице «тип факта → блок». Например, «шаги процесса» → `order`, «найди лишнее / подделку» → `odd-one-out`, «собери набор» → `build`. Правила вопросов: опираться на факты брифа и ничего не выдумывать про продукты.
  6. Выполнить `quiz:check` и чинить, пока не станет зелёным.
  7. Выполнить `quiz:shots` и осмотреть скриншоты.
  8. Выполнить `quiz:preview`.
  9. Внести правки клиента.
  10. Запустить.
- **Чек-лист перед запуском:** юр.тексты не плейсхолдер (уже есть `launch-checks.ts`), SMTP, домен.

### Этап 6. Хостинг
- **Общий сервер.** Wildcard DNS `*.<домен>` и Caddy on-demand TLS для кастомных доменов. Арендатор определяется по Host.
- **Админка на арендатора.** Пароли хранятся хешами в БД (таблица `TenantAdmin`), а не в пакете.
- **ПДн.** Клиент — оператор, мы — обработчик. В каждом пакете своя `legal`, в договоре — поручение на обработку.
- **Сервер клиента.** Тот же образ с `TENANT=<slug>`, деплой текущими скриптами `deploy/`.

## Порядок и оценка
1. Этапы 0–1 (пакет, загрузчик, диапазоны) — основа, без неё ничего не масштабируется.
2. Этап 2 (бренд) и этап 4 в объёме `quiz:check` и `quiz:shots` — после этого можно собрать первого СМБ-клиента в режиме карточек.
3. Этап 5 (скилл и бриф) — прогон на 2 фейковых брифах: кофейня и тайский спа.
4. Этап 3 (миры): сначала `world.json` для существующего шара, потом новые миры и редактор.
5. Этап 6 (мульти-домены и админки) — к первым продажам.

Целевой результат: от брифа до превью меньше одного рабочего дня, работа человека — только приёмка.

## Проверка
- Эталонный пакет `demo-office` проходит все текущие тесты: `npm test`, `npm run lint`, build, `npm run test:e2e`. Это доказательство, что рефакторинг ничего не сломал.
- Unit-тесты на схему: диапазоны количеств, пороги в %, связь рывок ↔ зоны, иконки, связность графа мира.
- e2e, параметризованные по арендатору: полный путь игрока на `demo-office` и на `demo-coffee`.
- Приёмка агента: в чистой сессии Claude Code и отдельно в Codex скилл собирает пакет по `docs/brief-template.md`, заполненному для кофейни. `quiz:check` зелёный, скриншоты без поломок вёрстки, превью открывается, идеальный проход даёт верхний уровень приза.
