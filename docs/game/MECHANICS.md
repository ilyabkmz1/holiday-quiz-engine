# Игровая механика движка

Нейтральная спецификация механики квиза и квеста. Контент (сюжет, герои, тексты заданий, призы) живёт в пакете арендатора `tenants/<slug>/`; здесь описаны только правила, общие для всех пакетов. Эталон, на котором держатся тесты, — `tenants/demo-office/` (вымышленный «Северный офис» в мире `snow-globe`).

Источники истины в коде:

- контракт кампании и проверки контента — `src/config/schema.ts`;
- разбор ответов — `src/domain/tasks.ts`;
- очки, бонусы, уровни — `src/domain/scoring.ts` (константы `SCORING`);
- финальный рывок — `src/domain/rush.ts` (константы `RUSH`) и `src/server/services/rush-service.ts`;
- сессии и заявки на приз — `src/server/services/session-service.ts`, `claim-service.ts`.

Если числа ниже расходятся с кодом, прав код.

## 1. Структура игры

1. **Пролог** без очков: герой-ведущий (`prologue.heroId`) произносит реплики `prologue.lines`, затем обучающий тап — включить двухфакторный вход (`prologue.mfa`: `prompt`, `switchLabel`, `done`).
2. **Зоны (комнаты)** — 3–6 штук (`rooms[]`), в каждой 2–4 задания (рекомендуется 3). Игрок выбирает порядок зон сам; задания внутри зоны идут строго по очереди. Зона сначала открывается входом (`rooms/:roomId/enter`, время входа фиксируется один раз).
3. **Финальный рывок** — открывается после прохождения всех зон: 30 секунд на поток коротких заявок.
4. **Финал**: счёт, уровень награды, «игрушки на ёлку» (по одной за пройденную зону, поле `ornament`), заявка на приз с подтверждением email, карточка «Поделиться».

Герои: 1–8 (`heroes[]`), у каждого задания свой `heroId`; герой-«хозяин» зоны до первой заявки — `hostId` (по умолчанию герой первого задания).

## 2. Режимы подачи

`campaign.mode` выбирает только подачу; сервер, API, очки и сессии у режимов общие.

| Режим | Подача |
|---|---|
| `quest` (по умолчанию) | Мир-иллюстрация: персонаж ходит по дорожкам мира, герои стоят у своих зон, задание открывается компактной карточкой (нижний лист на телефоне, панель справа на десктопе). Рывок проходит в мире, у ёлки. |
| `cards` | Карта с кнопками зон и полноэкранные комнаты. Дешевле: миру нужны только фон и точки зон. |

Параметр `/?mode=cards` или `/?mode=quest` переключает подачу для показа и тестов.

### Привязка к миру

Мир — разметка иллюстрации `worlds/<id>/world.json`: граф дорожек, точки зон `spots[]` (площадка, место героя, прямоугольник комнаты, положение кнопки в режиме cards), места игрушек на ёлке, площадка рывка, рамки камеры. Зона пакета ссылается на точку полем `spotId` (по умолчанию — id зоны); `map` — положение кнопки зоны в режиме cards (берётся из `spots[].card`). Одна точка — одна зона, зон не больше точек мира. Связность графа и достижимость площадок от старта проверяют `src/worlds/world.ts`, `quiz:check` и старт приложения.

## 3. Типы заданий

У каждого задания общие поля: `id`, `heroId`, `say` (ситуация), `thanks` (после верного), `oops` (после ошибки), `tip`, `explanation`. Порядок вариантов перемешивается детерминированно по зерну «id сессии + id задания» (`src/server/shuffle.ts`): он не выдаёт ответ и не меняется при повторном запросе. Id вариантов должны быть нейтральными: схема отвергает слова-маркеры (`REVEALING_ID_PATTERN`: `correct`, `right`, `wrong`, `fake`, `genuine`, `trap`, `phish`, `spam`, `bad`, `good`, `true`, `false`).

| Тип | Действие игрока | Контент | Ответ (`payload`) | База |
|---|---|---|---|---|
| `pick` | выбрать одну карточку | `options` 3–4, `correctOptionId` | `{ optionId }` | 100 / 0 |
| `build` | собрать N карточек в N слотов | `slots` 2–4, `options` 3–6 (больше слотов: есть ловушки), `correctOptionIds` ровно `slots` | `{ optionIds }` ровно `slots` штук, порядок не важен | 100 без ошибок; 50 при ровно одной неверной карточке; иначе 0 |
| `phish` | найти подделку среди писем | `letters` 3–5 (отправитель, адрес, тема, отметка `none`/`verified`/`gov`, вложение), `fakeLetterId` | `{ optionId }` — id письма | 100 / 0 |
| `access` | выставить переключатели | `switches` 4–6, `correctEnabledIds` (минимум один, и хотя бы один переключатель остаётся выключенным) | `{ enabledIds }`, можно пустой список | 100 при точном совпадении; 50 при ровно одном неверно выставленном переключателе; иначе 0 |
| `order` | расставить карточки по порядку | `items` 3–4 (показываются не в верном порядке), `correctOrder` — перестановка `items` | `{ orderedIds }` со всеми карточками | 100 за точный порядок / 0 |

Неизвестные или повторяющиеся id в ответе, неверное число карточек — ошибка `400` без записи ответа.

## 4. Очки

Всё считает сервер по своим отметкам времени (`src/domain/scoring.ts`).

- **База задания** — 0, 50 или 100 по таблице выше.
- **Комбо** — серия подряд идущих заданий на 100 (по порядку ответов, сквозь зоны). Бонус за задание = 25 × (комбо − 1), не больше 75: первое задание серии бонуса не даёт. Задание на 50 или 0 обнуляет серию.
- **Предохранители** — в зоне их 3; каждое задание на 0 отнимает один. Это индикатор, игру он не останавливает.
- **Зона без сбоев** — +50, если в полностью пройденной зоне нет ни одного задания на 0.
- **Бонус скорости зоны** = ⌊max(0, 75 − секунды) × 2 × (база зоны / (число заданий × 100))⌋. Время задания — от первой выдачи задания сервером (`GET .../task`, таблица `TaskShown`) до ответа; время чтения разбора и паузы между заданиями не считаются; время зоны — сумма по её заданиям в целых секундах вниз. Повторная выдача и восстановление игры отметку не сдвигают. Если ответ пришёл без запроса задания, отсчёт идёт от предыдущего ответа или входа в зону. Умножение на долю базы не даёт заработать скорость на ошибках.
- **Финальный рывок** — +20 за каждый верный ответ.
- **Итог** = сумма итогов зон (база + комбо + без сбоев + скорость) + очки рывка.

### Максимум кампании

`maxScore(tasksPerRoom)`: все задания на 100, комбо сквозь все задания, «без сбоев» и мгновенная скорость (75 × 2) в каждой зоне, плюс плановые 15 верных заявок рывка (`SCORING.rushPlannedHits`). Для 5 зон по 3 задания это 1500 + 975 + 5 × 200 + 300 = **3775**; для 3 зон по 3 задания — **2325**.

## 5. Финальный рывок

- Длительность 30 с (`RUSH.durationMs`), отсчёт от старта на сервере (`rush/start`, идемпотентно, только после всех зон).
- Кнопки рывка — это зоны кампании: id сервисов `rush.services` совпадают с id зон (3–6 кнопок), каждый сервис должен быть верным ответом хотя бы на одну заявку.
- Пул `rush.pool` — не меньше 16 заявок, у каждой `serviceId` (зона-ответ) и флаг `security`; ровно 3–4 заявки про безопасность. Сервер перемешивает пул при старте и выдаёт заявки по одной (`rush.current`).
- На каждую заявку принимается один ответ: верный — +20 очков; неверный тоже закрывает заявку и сдвигает дедлайн сервера на 2 с раньше (`RUSH.penaltyMs`).
- Ответы принимаются до дедлайна + 2 с допуска на сеть (`RUSH.graceMs`); позже — `400`. Рывок заканчивается по дедлайну, когда пул исчерпан, или вызовом `rush/finish` (идемпотентно).
- Клиентский таймер строится по `deadlineAt` и `serverNow` и нужен только для показа.

## 6. Уровни наград

`rewardTiers[]` — 2–5 уровней. Порог задаётся абсолютными очками `minScore` или долей от максимума `minPercent` (0–100, переводится в очки от `maxScore` с округлением). Нижний уровень начинается с 0, пороги строго возрастают; если заданы оба поля, они должны совпадать. Уровень игрока — самый высокий, порог которого не больше счёта (`resolveReward`). У уровня есть `title`, `description`, `giftLabel`.

`quiz:check` симулирует идеальный и нулевой проход на настоящих сервисах: идеальный должен дать `maxScore` и высший уровень, нулевой — нижний.

## 7. Косметические бонусы: искорки

В режиме квеста на дорожках мира лежат искорки (примерно одна на каждые 120 единиц дорожки). Они цепочкой ведут к следующей цели, каждые 8 собранных — трюк робота-помощника и «встряхивание» шара, в финале ими украшается ёлка, число попадает на карточку «Поделиться». **На серверный счёт искорки не влияют**: список собранных хранится только в `sessionStorage` браузера.

## 8. Заявка на приз

После `complete` игрок оставляет имя, email, компанию и согласие (`claim`); приходит письмо со ссылкой подтверждения. Заявка уникальна по паре `[campaignSlug, normalizedEmail]`: один приз на email в рамках кампании. Повторный переход по уже использованной ссылке показывает успех без изменений (ссылки открывают почтовые сканеры). Окна приёма и подтверждения — `claimEndsAt` и `verificationEndsAt` кампании.

## 9. Серверные инварианты

- Очки, комбо, бонусы, время и дедлайн рывка считает только сервер по своим отметкам времени; клиентские таймеры — только для показа.
- Правильные ответы и признаки правильности (`correct*`, `fakeLetterId`, `explanation`, `tip`, `thanks`, `oops`) не уходят клиенту до фиксации ответа на это задание. Публичное представление собирает `src/server/presentation.ts` явным списком полей; разбор (`reveal`) приходит только в ответ на `answers`.
- Идемпотентны: вход в зону, ответ на задание (повтор возвращает первый разбор и не меняет счёт), ответ на заявку рывка (один на заявку), старт и завершение рывка, финализация результата (`complete`).
- Порядок игры соблюдается сервером: задания зоны — по очереди, рывок — после всех зон, `complete` — после всех ответов и завершённого (или истёкшего) рывка; нарушение — `409`.
- Подтверждение заявки и уникальность нормализованного email атомарны; токены подтверждения хранятся только хешем.
- В логи не попадают email, поля формы, токены подтверждения, SMTP- и admin-секреты.
- Механика сессий не зависит от контента: задания, названия и бренд — только в пакете.
- Интерфейс поддерживает клавиатуру (цифры 1–9 выбирают карточки и сервисы) и `prefers-reduced-motion`.
