# Сборка квиза под ключ

Агент **заполняет данные пакета**, а не пишет код. Движок общий; квиз клиента — папка `tenants/<slug>/` с `pack.json` (схема — `src/config/pack.ts`, `src/config/schema.ts`, `src/config/brand.ts`). Ошибки ловит `npm run quiz:check`, а не ревью кода. Одинаково работает в Claude Code и Codex. Правила игры (типы заданий, очки, финальный рывок, уровни) — `docs/game/MECHANICS.md`.

Эталоны: `tenants/demo-office/` — полный пакет квеста (вымышленный «Северный офис», мир `snow-globe`, пять зон, все пять типов заданий, пролог, финальный рывок, четыре уровня; TS-модули `campaign.ts`/`legal.ts`/`pack.ts`), `tenants/demo-coffee/pack.json` — пакет режима карточек, собранный по брифу. Смотрите в них, как заполнены поля, но не копируйте их тексты и не правьте их: на `demo-office` держатся тесты движка.

Пакеты реальных клиентов не коммитьте в публичный репозиторий движка: держите их в приватном репозитории и копируйте в `tenants/` при сборке (README, раздел «Как добавить приватный пакет клиента»).

## Запрещено

- Править `src/`, `prisma/`, `deploy/`, чужие пакеты и тесты, чтобы «пролезла» проверка. Если схема мешает, остановитесь и напишите, чего не хватает движку.
- **Выдумывать факты о продуктах клиента.** Вопросы строятся только на фактах из брифа. Нет факта — задайте клиенту вопрос.
- Класть в пакет секреты, `.env`, пароли, исходные презентации.
- Включать `QUIZ_FORCE_OPEN`/снимать staging-пароль, переводить стенд в production без команды владельца (см. `AGENTS.md`, раздел про деплой).
- Оставлять в `pack.json` слова `TODO`: `quiz:check` их не пропустит.

## Шаги

### 1. Разобрать бриф и задать вопросы только по пробелам
Шаблон — `docs/brief-template.md`, пример — `docs/examples/brief-demo-coffee.md`. Прочитайте бриф целиком. Пустое («—») и неясное соберите в **один** список вопросов клиенту (не по одному). Обязательно нужно: название бизнеса, 3–5 тем с фактами, призы и уровни, даты, юрлицо. Без фактов по теме зону не создавайте.

### 2. Создать пакет
```bash
npm run quiz:new -- <slug> --brief путь/к/brief.md --zones <3–5>
```
Slug — латиница и дефис (`demo-coffee`). Команда создаст `tenants/<slug>/pack.json` с заготовкой, перенесёт поля брифа и зарегистрирует пакет в `tenants/index.ts`.

### 3. Собрать brand kit
- Есть сайт: `npm run quiz:brand -- <slug> <url>`; цвета и шрифт проверьте глазами, затем `--apply`. Логотип и картинки положите в `public/tenants/<slug>/` и укажите `/tenants/<slug>/logo.svg` в `brand.logo`.
- Нет сайта: палитра из брифа или тёплая/холодная тёмная палитра по тону бизнеса.
- Игра **тёмная**: `bg` и `panel` тёмные, `ink` светлый. Схема отвергает палитры с контрастом ниже WCAG AA — подберите цвета, а не отключайте проверку.
- Шрифт только из allowlist: `onest`, `inter`, `manrope`, `montserrat`, `nunito`, `rubik`.

### 4. Выбрать мир
Сейчас один мир — `snow-globe` (иллюстрация «офис в снежном шаре», 5 точек зон). Режим для новых клиентов — `"mode": "cards"`; квест (`"mode": "quest"`) работает на любом мире: зона привязывается к точке через `spotId`, id зоны с ним не связан. Нужен мир под нестандартный бизнес (спа, детсад) — пометьте в отчёте «нужен свой мир» (этап 3 плана движка), не изобретайте.

| Сегмент | Мир |
|---|---|
| любой, пока нет других миров | `snow-globe` |
| магазин, кафе, салон | `winter-street` (в плане, ещё нет) |
| спа, детсад, клиника | `cozy-house` (в плане, ещё нет) |
| склад, производство, доставка | `workshop` (в плане, ещё нет) |

### 5. Метафора и маппинг «тема → зона»
- Каждой теме — одна зона: `rooms[]` (3–5 на snow-globe). `id` зоны латиницей, без слов-подсказок.
- `rush.services[]` — кнопки финального рывка: те же зоны (id совпадают), по одной кнопке на зону; в `rush.pool` не меньше 16 коротких задач-«ситуаций», у каждой `serviceId` = зона-ответ; ровно 3–4 задачи с `security: true` (для бизнес-квиза — про безопасность, гигиену, ответственность).
- Метафора: «игрушки на ёлку» зашита в `copy` по умолчанию; поменять можно полями `copy` и `story` (заголовок места, реплика гида, подписи итоговой карточки).
- Героев 1–8, каждый ведёт свои задания (`heroId`). Имена и роли выдумайте нейтральные.
- Привязка зоны к миру: `spotId` — id точки мира (`spots[].id` в `worlds/<мир>/world.json`), а `map` — положение кнопки зоны на карте режима cards; оно берётся из той же точки (`spots[].card`). `quiz:new` расставляет оба поля из заготовки, не правьте их вручную. Если всё же меняете `spotId`, скопируйте `card` новой точки в `map`. Id зоны с точкой не связан. Одна точка — одна зона, зон не больше точек мира (на snow-globe их 5); неизвестную точку, две зоны на одной точке и расхождение `map` ловит `quiz:check`.

### 6. Сгенерировать задания по таблице «тип факта → блок»

| В брифе есть… | Блок | Заметки |
|---|---|---|
| правило, число, выбор «как правильно» | `pick` | 3–4 варианта, один верный |
| шаги процесса, этапы пути | `order` | 3–4 шага; в `items` порядок **не** верный |
| набор из нескольких верных пунктов | `build` | `slots` 2–4, вариантов больше слотов (есть ловушки) |
| чек-лист «что включить / настроить» | `access` | 4–6 переключателей, часть — ловушки |
| найти подделку / нарушение среди нескольких | `phish` | 3–5 писем-карточек, ровно одна подделка (`fakeLetterId`) |

Правила:
- 2–4 задания на зону (рекомендуется 3), типы чередуйте; в квизе должно быть не меньше двух типов.
- `id` вариантов — нейтральные слова (`alpha`, `roast-date`), **без** `correct/right/wrong/fake/good/bad/true/false/trap/phish/spam`.
- У каждого задания заполнены `say` (ситуация), `thanks`, `oops` (объясняет мягко, без упрёков), `tip`, `explanation` (по фактам брифа).
- Длины: `say` ≤ 220, `thanks`/`oops` ≤ 220, `explanation` ≤ 460, вариант ≤ 70, заголовок зоны ≤ 24 знаков (`quiz:check` предупредит).
- Иконки (`icon`) — только из `src/config/icon-paths.ts`: `at bell board bot cal car chart check clip clock disk download forward globe image key lock mail msg pencil phone proj scissors trash users video gift share`.
- Призы: `rewardTiers[]` — 2–5 уровней, нижний `minScore: 0`; остальные `minPercent` (доля от максимума, рекомендуем 45 / 75 для трёх уровней). У каждого `title`, `giftLabel`.

### 7. Прогнать проверку и чинить до зелёного
```bash
npm run quiz:check -- <slug>
```
Ошибки (`✗`) устраните все. Предупреждения (`!`) прочитайте: длинные тексты сократите, «высший уровень недостижим без бонуса скорости» — снизьте процент. Юридический маркер «на согласовании юриста» допустим на демо и превью, но не в production.

### 8. Посмотреть скриншоты
```bash
TENANT=<slug> QUIZ_FORCE_OPEN=true npm run dev        # в другом терминале; нужны PostgreSQL и SMTP из .env
npm run quiz:shots -- <slug>
```
Откройте PNG из `shots/<slug>/` (mobile и desktop) и проверьте: текст не обрезан, кнопки зон не перекрываются, контраст читаем, логотип на месте. Исправьте `pack.json` и повторите шаги 7–8.

### 9. Превью
`npm run quiz:preview -- <slug> --base-domain <общий домен>` проверяет пакет и git-состояние и печатает шаги; с `--ssh U@H --deploy` выкатывает через `deploy/deploy.sh` на адрес `https://<slug>.<общий домен>/`. Выкатку делайте только по команде владельца. Превью всегда за staging-паролем.

### 10. Правки клиента и запуск
Вносите правки только в `pack.json`, после каждой — `quiz:check`. Перед запуском пройдите чек-лист.

## Чек-лист перед запуском

- [ ] `quiz:check` без ошибок; предупреждения прочитаны.
- [ ] Юридические тексты `legal` утверждены юристом клиента (нет маркера «на согласовании»; в production запуск без этого запрещён — `src/server/launch-checks.ts`), оператор ПДн — юрлицо клиента.
- [ ] Факты в заданиях подтверждены клиентом.
- [ ] Даты кампании верны, часовой пояс МСК.
- [ ] SMTP настроен (письмо с подтверждением email доходит), тема письма — `brand.mailSubject`.
- [ ] Домен и TLS, `TENANT=<slug>` либо `hosts` в пакете.
- [ ] Скриншоты mobile и desktop осмотрены.
- [ ] Бэкап БД и проверка восстановления (`deploy/README.md`).
